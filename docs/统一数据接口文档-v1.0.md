### 1.1 第 5 条为什么砍（唯一一条覆盖了组员答复的决定）

| 理由 | 说明 |
|---|---|
| **工作量硬约束** | 《任务拆解》算过：初版需 **≈70 人日**，两周可用**约 30 人日**，缺口一倍多 |
| **测不准** | "死亡个体数量""个体体长离散度"**在图像上难可靠测量**——做出来也是不可信的数字 |
| **口径冲突** | `fcr` 是"饵料转化率"，算它等于在算投喂效率——**而投喂已归智能板块**（第 1 条） |
| **答辩风险** | 依据不硬的功能是**负债**，被问到"这个数怎么来的"答不上来 |

> **依据**：《会前比对-1003》第五节、《任务拆解-到10-16》第十二节。**若队长日后要恢复，需重新计入人日。**

### 1.2 第 9 条为什么"扩"而不是"砍"

不扩模拟器 → 结构安全的锚泊张力、网衣监测、结构形变、能源保障**四块全部禁用灰显** → 10-16 初版只剩"灾害分级预警"一块能演示；
且**模拟器同时是全项目唯一的造故障工具提供方**，断它会连带断掉整个闭环证据链。

> ⚠️ **一处尚未裁定的冲突**：第 9 条把**数据源备齐了**（2 人日），但《任务拆解》第十二节建议把"网衣监测 / 结构形变 / 能源保障"三个模块**砍掉**。
> 即：**模拟器扩了，可能没有页面用**。此为**独立问题**，列入 `功能冻结清单-10-05.md` 的「待裁定」区，**本文件不代它决定**。
> 选择"扩"的理由：**只减不加**——数据源后补成本高，页面后砍成本低，先备着可逆。

### 5.5 🆕 邓宇涵的传感器答复（2026-10-05 17:47 收到，已并入本文件）

| # | 物理量 | 单位 | 用途 |
|---|---|---|---|
| 1 | 锚链 / 缆绳张力 | kN | 锚泊张力预警；**同时提供设计张力**，算 80% / 95% 阈值 |

| 5 | 光伏发电功率 | kW | 能源供给 |
| 6 | 储能电量 SOC | % | 20% / 10% 低电量预警 |

**因这份答复而对本文件做的修正**（已记入第十三节变更记录）：

|---|---|---|
| `accel`（单个 float） | **`accel_x` / `accel_y` / `accel_z`** | 答复明确要**三轴**；单值表达不了 |
| `tilt_angle`（单个 float） | **`tilt_roll` / `tilt_pitch`** | 答复明确要**横滚 / 俯仰两向** |

> ⚠️ **一处被答复明确否掉的写法**：答复里提到"电压传感器（V）/ 电流传感器（A）"。
> 但答复自己也写了"**建议统一 kW**"。
> **本文件按 kW 定**（`pv_power` / `device_power`），电压电流是**设备内部实现**，不进接口字段。
> **理由**：规范 2.1 要求全项目统一单位，多一套 V/A 只会让三个板块各算各的。

> ✅ **#5 至此闭环**：① 邓宇涵的设备与字段清单 → **本份答复**；② 李志成模拟器扩不扩 → **裁定 9（扩 7 类）**。
> **项数争议（5 类 / 7 类）一并定死为 7 类。**

## 七、数据缺失与枚举约定

### 7.1 数据缺失怎么表示

| 情况 | 字段给什么值 | 附加标记 | 页面怎么显示 |
|---|---|---|---|
| 设备离线 | `null`（**不给上一个值**） | — | 数值位显示 `—`，角落标"设备离线" |
| 数据超时未更新 | `null` | `quality = "stale"` | 数值变灰 + "最后更新于 xx:xx" |
| 数值异常（超量程） | **保留原值** | `quality = "suspect"` | 数值黄色 + 提示"疑似异常" |
| 传感器未接入 | `null` | — | 整个模块**灰显**，标"传感器未接入"，**不参与评分** |

> 🔴 **一条硬纪律：离线不许给上一个值。** 给了上一个值，页面显示还是 `18.6℃`，看着一切正常，实际设备早断了。
> **不允许静默失败 —— 这是全项目的立身之本。**

| 值 | 中文 | 颜色 |
|---|---|---|

### 7.6 `command_status` 取值（**答辩演示重点**）

```
created → sent → acknowledged → success
              ↘ timeout → retrying → failed
                              ↘ escalated
```

| 值 | 中文 | 含义 |
|---|---|---|
| `created` | 已创建 | 平台生成了这条命令 |
| `sent` | 已发出 | 命令已发给设备 |
| `acknowledged` | 已收到回执 | 设备回话说"我动了" |
| `success` | 成功 | **确认设备真的动了** |
| `timeout` | 超时 | 等太久没回话 |
| `retrying` | 重试中 | 再发一次 |
| `failed` | 失败 | 重试几次还不行 |
| `escalated` | 升级报警 | **通知到人** |

| 值 | 中文 |
|---|---|
| `none` | 无 |
| `weak` | 弱 |
| `mid` | 中 |
| `strong` | 强 |

### 8.1 站点

| `site_id` | 类型 | 说明 |
|---|---|---|
| `site_01` | **模拟养殖站点** | 深远海网箱场景（`cage_01`）；数据 = 仿真 + 公开数据驱动 |
| `site_02` | 环境观测站点 | NOAA NDBC 公开浮标 |

**编号规则**：`site_` + **两位数字**（`site_01`）。设备编号 `{类型}_{两位数字}`，**不带站点前缀**（`site_id` 已是独立字段）。

### 8.2 🔴 对外口径（**说错就是答辩硬伤**）

> **统一原话**：
> **"采用 NDBC 真实浮标海域数据作为环境驱动，站点为模拟养殖站点。"**

| ✅ 可以这么说 | ❌ 不许这么说 |
|---|---|
| 环境数据来源**真实**（NDBC 公开浮标） | 说成"**真实养殖基地**数据" |
| 场景是**模拟**的深远海养殖站点 | 说成"我们对接了某养殖企业" |
| 数据来源在界面上**逐一标注** | 把仿真数据说成真实数据 |

> **数据来源真实是加分项，场景不要说成真实养殖基地。** 主动标出来源反而是加分项——
> **用假数据装成真的，才是答辩时最容易被戳穿的事。**

### 8.3 数据来源标注话术（全项目统一）

> **"平台数据通过标准接口接入，演示环境用仿真数据和公开数据，接口已留好，随时能接真实数据。"**

## 九、指令接口（三条 · ✅ 本文件定稿）

| 接口 | 方向 | 传什么 | 谁提供 |
|---|---|---|---|
| **下发指令** | 后台 → 接入层 | `command_id` `device_id` `command_type` 参数 `timeout_ms` | 李志成 |
| **查询指令执行结果** | 任意板块 → 智能 | `command_id` → `command_status` `receipt_result` `retry_count` | 李志成 |
| **查询设备实时状态** | 任意板块 → 智能 | `device_id` → `device_online` `device_state` `device_params` | 李志成 |

```json
// 下发指令（示例）
{
  "command_id": "cmd_20261005_0001",
  "device_id": "feeder_01",
  "command_type": "feed",
  "params": { "amount_kg": 12.5 },
  "timeout_ms": 5000,
  "ts": 1758969600000
}
```

```json
// 返回回执（示例）
{
  "command_id": "cmd_20261005_0001",
  "success": true,
  "result": "executed",
  "actual_ts": 1758969604200,
  "error_code": null
}
```

```json
// 出错返回（统一格式）
{ "code": 503, "msg": "设备离线" }
```

| code | 含义 | 什么时候用 |
|---|---|---|
| `200` | 正常 | — |
| `400` | 参数错误 | 字段缺失、类型不对、超时时间非法 |
| `404` | 对象不存在 | 设备号 / 站点号查不到 |
| `503` | 设备离线 | 命令发不下去、取不到数据 |
| `504` | 数据超时未更新 | 接口连得上，但数据是旧的 |
