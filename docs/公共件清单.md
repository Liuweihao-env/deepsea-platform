## 二、逐件说明

### ① 平台骨架 + 前端框架　→ 我们

| 项 | 内容 |
|---|---|
| **是什么** | 菜单结构、页面布局、通用组件（数值卡 / 时序曲线 / 事件列表 / 时间窗切换 / 数据来源标签 / 状态色阶）、路由 |
| **为什么是公共件** | 全项目的门面。没人管 → 四个风格各异的页面，不像一个网站 |
| **已定** | 菜单结构（4 板块 + 总览，共 11 页）、统一布局（顶部横条 + 左侧菜单 + 主内容区 + 操作条） |
| **没做** | **代码一行没写**；四个全局页的菜单位留了但归属未定 |
| **交付** | **10-05 定第一版**，发给王浩然/刘伟豪/邓宇涵/李志成照它填页面 |
| **验收** | 三名组员各填 1 个页面，**不需要问我们** |
| **卡什么** | 无。**这是我们唯一完全自主、不依赖别人的公共件** |

### ② 统一数据接口文档　→ 李志成主责，我们出前端部分

| 项 | 内容 |
|---|---|
| **是什么** | 全局字段表：字段名（英文）、类型、**单位**、频率、缺失表示；以及接口清单 |
| **为什么是公共件** | 接口不定死，四个板块的数据拼不到一起。**"没有数据库、只准备接口"是项目的立身方式** |
| **现状** | 🔴 **四份产品文档都写"通过标准化 API 输出"，但没有任何一份给过字段名。全局字段表是空的** |
| **交付** | **10-05 硬线**，写完通知全员确认 |
| **接口文档必须写清 6 件事** | 字段名、类型、**单位**、时间格式（统一毫秒数）、出错返回什么、一段示例数据 |
| **卡什么** | 卡王浩然/刘伟豪/邓宇涵各自交字段。**这是全项目最大的单点缺口** |
| **注意** | **同一个东西不许起两个名字** —— 你叫 `water_temp`、别人叫 `temp`，接口就对不上 |

### ③ 设备模拟器　→ 李志成

| 项 | 内容 |
|---|---|
| **是什么** | 用程序模拟受控设备；正常执行返回成功回执，也能**故意造故障** |
| **为什么是公共件** | 所有"操控"功能的公共底座（自动投喂、智能补光、灾害处置都要用）；也是**没有硬件也能证明闭环的唯一凭据** |
| **现状** | 🟠 只覆盖**投饵设备、补光灯具**两类；四类故障仿真（离线 / 超时不回复 / 执行失败 / 返回异常参数）已设计 |
| **交付** | 10-12 能用 |
| **🔴 断点** | **结构安全要 7 个字段没覆盖**：锚链张力、网绳拉力、倾角、加速度、光伏发电、储能电量、设备功耗 |
| **后果** | 不扩 → 结构安全的锚泊张力、网衣监测、结构形变、能源保障**四块全部禁用灰显** → 10-16 初版只剩"灾害分级预警"一块能演示 |

### ④ 指令状态机　→ 李志成

| 项 | 内容 |
|---|---|
| **是什么** | 统一指令封装（命令ID/设备ID/类型/参数/时间戳）、超时重试、失败报警、全链路日志、三个对外接口 |
| **为什么是公共件** | 全项目卖点的载体："别人做到'我把命令发出去了'，我们做到'我知道设备到底动没动'" |
| **现状** | 设计完整。状态流转：`已创建→已发出→已收到回执→成功` / `↘超时→重试中→失败→升级报警` |
| **交付** | 10-05 三条接口定稿 → 10-19 完整流程 |
| **硬纪律** | **命令发出去没回执必须报警，绝对不允许"悄悄地失败"** |
| **卡什么** | 无重大问题 |

### ⑤ 规则引擎 + 测试验证　→ 邓宇涵

| 项 | 内容 |
|---|---|
| **是什么** | 可配置阈值规则 + 组合条件（如"浪高>3m 且 锚泊张力>设计值80%"→橙色）；每条预警记录触发数据快照 + 命中规则 ID + 时间戳。外加造故障工具、测试用例、验证报告 |
| **为什么是公共件** | "闭环要拿证据说话"——**证据就是测试用例和测试报告**。也是全项目唯一的造故障工具 |
| **现状** | 规则引擎设计完整；测试报告未开始 |
| **交付** | 规则引擎 10-15；**测试报告 10-26** |
| **测试必须覆盖四类** | 数据异常、设备离线、命令超时、通信中断 |
| **卡什么** | 造故障工具要**别人也能调用**（王浩然要看界面、李志成要测重试），**调用方式还没写** |

### ⑥ 站点与主数据口径　→ 我们定（**新识别**）

| 项 | 内容 |
|---|---|
| **是什么** | 几个站点、怎么编号（`site_01`？）、网箱编号、设备编号规则 |
| **为什么是公共件** | 四个板块的数据全靠 `site_id` 关联。编号不统一，数据就散了 |
| **现状** | 🔴 **环境文档写 3 个 NOAA 站点，鱼类文档写"预计使用多个真实养殖基地"——两边对不上** |
| **交付** | 10-05 |
| **顺带要定的** | 站点口径怎么对外说（站点 1 在美国东海岸，**不是深远海养殖海域**，别说成"真实养殖基地"） |

### ⑦ 告警 / 处置 / 追溯三个跨板块页　→ **归属未定**（**新识别**）

| 项 | 内容 |
|---|---|
| **是什么** | 告警中心（分级预警）、处置中心（走指令状态机）、追溯查询（哪条数据→命中哪条规则→结果） |
| **为什么是公共件** | 灾害预警（结构安全）、投喂动作（智能）、鱼类异常（鱼类）都要进**同一个**告警中心 |
| **现状** | 🔴 我在鱼类文档里建议"顶层统一做"，但**没人认领** |
| **后果** | 各做各的 → 四个告警页，拼接时必然打架 |
| **交付** | 10-05 定归属 |
| **倾向** | **顶层统一做一套**，各板块只提供数据。答辩时"一个告警中心能看到所有板块的异常"本身就是卖点 |

### ⑧ 数据来源标注与统一口径　→ 我们定（**新识别**）

| 项 | 内容 |
|---|---|
| **是什么** | 界面上的"真实 / 公开 / 仿真 / 演示"标签样式；对外统一话术 |
| **为什么是公共件** | 纪律 4 要求每个数据都标来源；**用假数据装成真的，是答辩时最容易被戳穿的事** |
| **现状** | 🟠 四份文档都提到要标，但标签样式与口径没统一 |
| **交付** | 10-05 |
| **统一话术** | "平台数据通过标准接口接入，演示环境用仿真数据和公开数据，接口已留好，随时能接真实数据" |
| **加分点** | **主动在界面上标出来源，反而是加分项** |

## 三、依赖关系

```
                    ① 平台骨架 / 前端框架（我们）
                              │
                              │ 三个组员照它填页面
                              ▼
  ② 统一数据接口 ────────► 四个板块的取数与送数
        ▲   ▲   ▲
        │   │   └── 王浩然 / 刘伟豪 / 邓宇涵 各交自己的字段
        │   │
        │   └────── ③ 设备模拟器（李志成）──► 结构安全 7 字段  ← 🔴 断点
        │                    │
        │                    ▼
        │            ④ 指令状态机（李志成）
        │                    │
        │                    ▼
        └──────────── ⑤ 规则引擎（邓宇涵）──► ⑦ 告警/处置/追溯页
                             │
                             ▼
                     测试验证 + 造故障  ←── 全项目闭环的证据
```

**最要命的一根线**：`③ 设备模拟器 → 结构安全 7 字段`

> 李志成不扩 → 结构安全四块禁用 → **它同时还是"造故障工具"的提供方** → 全项目闭环证据链一起断。
