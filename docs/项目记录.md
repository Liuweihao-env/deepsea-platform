### 1.2 兼的活（公共件）也定了

每个板块都要用、但不属于任何板块的东西，一共四类，随人分配：

| 公共件 | 谁负责 | 为什么必须有人管 |
|---|---|---|
| **统一数据接口 + 数据格式** | **李志成（智能）** 主责；**王浩然**出前端要用的部分 | 接口不定死，四个板块的数据拼不到一起 |
| **平台骨架 + 前端框架**（菜单、布局、通用组件） | **刘桐麟（队长）** | 没人管就会得到四个风格各异的页面，不像一个网站 |
| **设备模拟器 + 指令状态机** | **李志成（智能）** | "操控"这条线全靠它，自动投喂/智能补光/灾害处置都用 |
| **规则引擎 + 测试验证**（造故障、写测试报告） | **邓宇涵（结构安全）** | "闭环"要拿证据说话，缺了它没东西可验证 |

### 1.3 为什么兼职这么分

- **智能板块只有 2 项功能，工作量最轻**，所以把两件最关键的公共件（接口、模拟器+状态机）压在这里。**这两件是全项目的底座，智能板块延期 = 全项目延期。**
- **平台骨架 + 前端框架归队长**：它是全项目的门面，需要跨板块统一，放在统筹层最合适 —— 队长本来就要收集各板块的页面需求、出汇总清单，顺手把菜单和布局定掉。**（注意：原来的理由是"鱼类负责人自己要写 4 个页面，顺手统一"，2026-10-02 分工调整后这条理由已不成立。）**
- **结构安全板块的问题在"说不清"**（"能源保障"到底是什么还没定义），所以额外给它规则引擎这条明确的技术活，避免它卡在概念上空转。

> ⚠️ **注意**：公共件负责人有权拒绝别人直接改公共代码。要改，**提需求、提意见，先说一句**。

### 2.5 派发时统一说明的三件事

1. **这不是"写作文"，是"定范围"。** 每一条都要能回答"输入什么、输出什么、根据什么"。**写不出这三样的，先写成"本期不做"，不要硬写。**
2. **边界比功能更重要。** 一定要明确写出"本板块不做什么"。四个板块的边界如果重叠，最后会出现两个人做同一件事，或者一件事没人做。
3. **不清楚的事写进"需要拍板的问题"那一节，不要自己猜着往下做。** 猜错了，10-05 之后返工的成本比现在问一句高十倍。

### 5.2 接口 11 条待定 → 全部裁定

| # | 定什么 | 裁定结果 |
|---|---|---|
| 1 | 投喂量由谁算 | **智能（李志成）算**；鱼类只出观测类指标，不做投喂决策、不下发命令 |
| 2 | 预警阈值从哪来 | **标为"经验值"**，界面与文档统一写「经验阈值，未经现场标定」；**不编标准号** |
| 3 | 盐度 / pH 频率 | **30 秒**（慢变量）；其余环境量保持 5 秒 |
| 4 | 站点数量与编号规则 | **4 个**：`site_01` 模拟养殖站点 + `site_02/03/04` 环境观测站点 |
| 5 | 鱼类 5 项指标取舍 | **本期不做** `dead_count` `length_cv_pct` `fcr` `activity_index`（覆盖答复单原答"全部做"） |
| 6 | `light_intensity` 谁提供 | **环境板块新增**这一项（lux / 5 秒） |
| 7 | 智能补光的依据 | **本期不做自动模式，只留接口 + 手工模式**（依据查不到出处，按规矩不编） |
| 8 | 超时 / 重试默认值 | `timeout_ms = 5000`、`max_retry = 3`，现场可调 |
| 9 | 模拟器扩不扩到结构安全传感器 | **扩，7 类全覆盖** |
| 10 | `salinity` 单位 | **`‰`** |
| 11 | 告警 / 处置 / 追溯页归属 | **顶层统一做一套（B 案）**，各板块只提供数据 |

### 5.3 规范待确认 A–F → 全部裁定

| 编号 | 裁定 |
|---|---|
| A | `do` → **`dissolved_oxygen`**（`do` 在 Python 里 `data.do` 直接语法错误） |
| B | 站点 **4 个**（原建议 3 个，改为 4 个以容纳鱼类养殖站点） |

| F | 精度：温度/溶氧/盐度 **1 位**；pH **1 位**；指数类 **0–2 位**；重量 **1 位** |
