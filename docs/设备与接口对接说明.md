# 设备与接口对接说明（答辩 Q3 的答案）

**编制**：刘桐麟（队长）　**版本**：v1.0　**日期**：2026-10-03
**依据**：何舒玥老师 2026-10-02 23:58 答复

> **何老师原话**："我们可以说清楚平台上要接的渔业设备，市场上主流的是哪些品牌，它们的接口是什么，**我们的平台正好就是这么设置接口的**。"
>
> **这份文件解决什么**：答辩问"**怎么证明真的有设备受你们操控**"时，我们不靠接线证明，靠**接口设计的现实依据**证明。

---

## 一、答辩时怎么讲（核心逻辑，先背下来）

> "我们是一个**无线网络通信的控制和数据采集终端**。
>
> 我们没有把传感器接到电脑上，也没有做下位机——**因为真实养殖场的设备本来就不这么接**。市面上主流的投饵机、增氧机、水质传感器，出厂就带**无线通信模块**（4G / LoRa / Wi-Fi），通过厂商的云平台或标准协议对外提供接口。
>
> **我们的平台就是按这些设备的实际接口形式来设计接入层的**，所以换成真设备，只需要配置，不需要改平台。"

**一句话**：**不讲"我们怎么接线"，讲"我们的接口是按现实设备的接口设计的"。**

## 二、要讲清楚的设备类别（内容框架）

答辩材料准备下表。**"接口形式"一列是重点**，也是何老师要的"它们的接口是什么"。

| # | 设备类别 | 在本项目里对应哪个板块 | 主流接口形式（**要讲的重点**） |
|---|---|---|---|
| 1 | **自动投饵机** | 智能（受控） | 厂商云平台 API / 4G 模块 / 部分支持 RS485 与开关量 |
| 2 | **增氧机** | 智能（受控） | 4G 远程控制器 / 定时器 + 继电器 / 部分仅本地控制 |
| 3 | **水下摄像机** | 鱼类（数据源） | 网络型 IP 摄像机（RTSP / ONVIF）/ 4G 图传 |
| 4 | **水质传感器**（水温、溶氧、pH、盐度） | 环境（数据源） | 无线浮标（4G / LoRa）/ 多参数一体机 / 部分 RS485 |
| 5 | **海况传感器**（浪高、风速、流速） | 环境（数据源） | 海洋浮标（铱星 / 4G）/ 气象站 |
| 6 | **结构监测传感器**（张力、倾角、加速度） | 结构安全（数据源） | 无线应变/倾角节点 / 采传一体机 |
| 7 | **供电系统**（光伏、储能） | 结构安全（数据源） | 逆变器 / 电池管理系统自带通信口 |

> **讲法**："这七类设备，我们每一类都留了对应的接入位。"

## 四、我们的接口怎么对应（**"正好就是这么设置的"**）

这张表是答辩的核心页面。**左边是市面设备的接口形式，右边是我们平台的接入位，一一对应。**

| 市面设备的接口形式 | 我们平台的对应设计 | 字段/接口 |
|---|---|---|
| 厂商云平台 **HTTP API** | 统一数据接口：环境时序数据 | `GET /api/env/latest` |
| 设备**主动上报**（4G 模组定时推） | 统一数据接口：接收上报 | `POST /api/env/report` |
| **下发控制指令** | 统一下发指令接口 | `POST /api/command/send` |
| **执行回执** | 查询指令执行结果接口 | `GET /api/command/{id}/result` |
| **设备状态查询** | 查询设备实时状态接口 | `GET /api/device/{id}/status` |
| **视频流**（RTSP/ONVIF） | 鱼类板块取帧接口 | `frame_seq` 字段 |
| **无线模组**（LoRa / 4G） | 通信层，平台不关心物理介质 | 只认标准接口 |

> **讲法**："左边任何一种市面设备的接口形式，右边都有对应的接入位。**我们不是设计了一套只有我们自己用的接口，而是照着行业已有的接口形式设计的。**"

## 五、答辩问答准备

### Q：你们真的接了设备吗？

> "没有接真设备。**但我们把接入层设计成了能直接对接市面上主流设备的形式** —— 上面这张对应表就是依据。换成真设备，只需要配置，不需要改平台。"

### Q：没接设备，怎么证明你们的控制是真的？

> "我们证明的不是'硬件被我们控制'，而是'**我们能确认设备到底有没有执行**'。
>
> 设备回执分三层：**① 已收到**（市面设备基本都有）**② 已执行**（部分有）**③ 真的生效了**（几乎没有，必须靠传感器反查）。
>
> **我们做的是第三层**：设备回执说投喂成功，但溶氧和鱼群活动都没变化 → 平台判定这条命令没真生效。**第三层是平台加上去的，不是设备给的。**"

### Q：你们的下位机/驱动是自己做的吗？

> "没做，也不打算做。我们是**上层平台**，负责协议、逻辑和可靠性，不碰电机和电路。真实场景里设备出厂就带通信能力。"

### Q：为什么不做 485 接线？

> "深远海现场不现实。传感器装在网箱上，离岸几十海里，不可能拉线到电脑上；现场的设备出厂也是走**无线模组或厂商云平台**。所以我们从设计上就走网络通信这条路。"
