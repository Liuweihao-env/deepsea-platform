# 一、命名规范

## 1.1 字段名（JSON / 接口 / 数据库）

| 规则 | 说明 | ✅ 正确 | ❌ 错误 |
|---|---|---|---|
| **全小写** | 不许大小写混用 | `water_temp` | `WaterTemp`、`waterTemp` |
| **下划线分词** | 不用驼峰、不用连字符 | `total_biomass_kg` | `totalBiomassKg`、`total-biomass` |
| **单位后缀** | 单位直接进字段名，避免歧义 | `avg_weight_g`、`wave_height_m` | `avg_weight`、`height` |
| **布尔用 `is_` / `has_` 前缀** | 一眼看出是是非题 | `is_online`、`has_alarm` | `online`、`alarm` |
| **时间戳用 `_ts` 后缀** | 与普通数值区分 | `actual_ts`、`created_ts` | `time`、`actual_time` |
| **不写单字母** | 除非行业通用缩写 | `temperature` | `t` |
| **不写拼音** | 拼音没人看得懂 | `salinity` | `yandu` |

### 必须避免的两个坑

| 坑 | 例子 | 问题 | 改法 |

# 二、单位规范

> **单位是最容易出错的地方**：温度是摄氏还是华氏？长度是米还是厘米？**写错一次，三个板块一起错。**

## 2.1 全项目统一单位（照这个表，不许自创）

| 物理量 | **统一单位** | 符号 | ❌ 不许用 |
|---|---|---|---|
| 温度 | 摄氏度 | `℃` | ℉、K |
| 长度（大） | 米 | `m` | cm、mm、尺 |
| 长度（鱼体） | 厘米 | `cm` | m、mm |
| 质量（大） | 千克 | `kg` | 吨、斤 |
| 质量（鱼体） | 克 | `g` | kg、斤 |
| 时间间隔 | 秒 | `s` | min、h |
| 时间戳 | 毫秒数 | — | 秒、字符串日期 |
| 速度（风/流） | 米每秒 | `m/s` | km/h、节 |
| 密度（鱼群） | 尾每立方米 | `尾/m³` | 尾/L |
| 溶解氧 | 毫克每升 | `mg/L` | ppm（虽等价，但统一用 mg/L） |
| 盐度 | 千分比 | `‰` | PSU（✅ **2026-10-05 已定用 `‰`**，见待确认 C） |
| 光照 | 勒克斯 | `lux` | lm |
| 功率 | 千瓦 | `kW` | W、马力 |
| 电量 | 百分比 | `%` | 安时 |
| 拉力 / 张力 | 千牛 | `kN` | kgf、N |
| 倾角 | 度 | `°` | 弧度 |
| 加速度 | 米每二次方秒 | `m/s²` | g |
| 面积/体积 | 立方米 | `m³` | L |
| 比值 / 指数 | 无单位 | — | — |

## 2.2 单位必须出现在两个地方

| 地方 | 要求 |
|---|---|
| **接口文档** | 每个字段的"单位"列**不许为空** |
| **页面上** | 数值卡、表格、坐标轴**都要带单位** |

> 页面上不写单位，等于没写。值班人看到 `18.6` 不知道是摄氏度还是别的。

# 四、缺失值与数据质量

## 4.1 怎么表示缺失

| 情况 | 字段给什么值 | 附加标记 | 页面怎么显示 |
|---|---|---|---|
| **设备离线** | `null` | — | 数值位显示 `—`，角落标"设备离线" |
| **数据超时未更新** | `null` | `quality = "stale"` | 数值变灰 + "最后更新于 xx:xx" |
| **数值异常（超量程）** | **保留原值** | `quality = "suspect"` | 数值黄色 + 悬停提示"疑似异常" |
| **传感器未接入** | `null` | — | 整个模块**灰显**，标"传感器未接入"，**不参与评分** |

## 4.2 🔴 一条硬纪律：离线不许给上一个值

> **设备离线时，字段必须给 `null`，不许给上一次的值。**

**为什么**：给上一个值，页面上显示的还是 `18.6℃`，**看着一切正常，实际上设备早就断了**。值班人根本发现不了。

**这就是"不允许静默失败"在数据层的落地。**

**注意区分两种情况**：

| 情况 | 做法 | 理由 |
|---|---|---|
| **设备离线** | `null` | 现在没有真实数据，必须让人看出来 |
| **页面加载中的占位** | 显示骨架屏 | 这是 UI 状态，不是数据状态，两者别混 |

# 七、接口返回格式与错误码

## 7.1 成功返回

直接返回数据本体，**不额外包一层**：

```json
{
  "ts": 1758969600000,
  "site_id": "site_01",
  "water_temp": 18.6,
  "quality": "good"
}
```

## 7.2 出错返回（**统一格式**）

```json
{ "code": 503, "msg": "设备离线" }
```

## 7.3 错误码表

| code | 含义 | 什么时候用 |
|---|---|---|
| `200` | 正常 | — |
| `400` | 参数错误 | 字段缺失、类型不对、超时时间非法 |
| `404` | 对象不存在 | 设备号/站点号查不到 |
| `503` | 设备离线 | 命令发不下去、取不到数据 |
| `504` | 数据超时未更新 | 接口连得上，但数据是旧的 |

## 7.4 接口文档必须写清 6 件事（**缺一项都算没写完**）

1. 字段名
2. 类型
3. **单位**
4. 时间格式（统一毫秒数）
5. 出错返回什么
6. 一段示例数据

## 8.3 🔴 脚本文件编码（**踩过坑，必须照做**）

| 类型 | 编码 | 行尾 | 为什么 |
|---|---|---|---|
| `.py` | UTF-8（无 BOM） | 不限 | Python 3 默认 |
| `.ps1` | **UTF-8 带 BOM** | 不限 | Windows PowerShell 5.1 按 ANSI 读不带 BOM 的脚本，**中文立刻变乱码、脚本直接语法报错** |
| `.bat` / `.cmd` | **纯 ASCII**（不许有中文） | **CRLF** | 见下 |
| `.md` / `.html` / `.js` / `.css` | UTF-8（无 BOM） | LF | — |

### ⚠️ 为什么 `.bat` 必须纯 ASCII + CRLF

**`cmd.exe` 是按控制台代码页（中文 Windows 上是 GBK）逐字节读 `.bat` 的**，不是按文件声明的编码。

于是 UTF-8 的中文（3 字节/字）被当成 GBK（2 字节/字）读，**行长变成奇数个字节，就会在行尾留下一个"悬空的前导字节"**。
这个悬空字节会把行尾的 `\r` 吞掉，**导致下一行与前一行粘在一起** ——
结果就是 **`REM` 注释行被当成命令执行**，控制台刷出一堆 `'1.' is not recognized as an internal or external command`。

**2026-10-05 实际踩过**：`启动平台.bat` 里的中文注释和中文提示全部乱码，并且报伪命令错误。
当时的现象是"看起来只是乱码"，**实际上是脚本在被错误地解析** —— 换成别人机器上可能直接不执行。

**所以规矩是**：
1. `.bat` 里**一个非 ASCII 字符都不许有**（注释也一样）；
2. 所有中文提示**交给 Python 打印** —— Python 在真实控制台用 `_WindowsConsoleIO` 直接写宽字符，**与 `chcp` 无关，任何控制台都正确**；
3. 行尾一律 **CRLF**（LF-only 的 `.bat` 在 cmd 里可能解析出错）；
4. `.gitattributes` 里锁死：`*.bat text eol=crlf`。

> 这条规矩同样适用于 `.cmd`。写新的启动脚本前先回来看一眼。
